# 启动、维护与故障定位

先读[本机实例](../references/local-instance.md)，需要接口说明时按需读[协议参考](../references/protocol.md)。本模块允许任务所需的本机文件和终端操作，不把平台 MCP 当作任意 Shell。

## 启动和接入

- 入口为项目的 Start-Workspace.cmd / Start-Workspace.ps1，后者支持 -NoBrowser。启动器默认端口为 8890，实际地址和数据目录以启动参数及 control.status 为准。
- MCP 启动参数必须有 `mcp --connect --compact --data-dir ACTUAL_PATH`。--connect 复用 HTTP 宿主；省略它会尝试启动独立 Runtime，占用同一数据目录。
- 先确定失败的是宿主、MCP 注册还是当前聊天未加载工具。用户要求启动平台时可执行启动器；仅询问配置或文档不自动启动服务。
- 配置落盘、MCP 握手成功、当前聊天工具可见是三个层次。工具清单缺少 oea 时，不假称已热加载。重开聊天或重新加载/重启客户端后再核验。

## 排错

运行中的双向报告、指导和定向诊断优先使用 [运维通道](operations.md)。先读短摘要和单个任务/工具回执，再取选中的报告正文；原始进程 stderr 不会自动保存为可读诊断日志，不假称已取得堆栈。需要更多证据时明确派发受管诊断任务或由执行端提交脱敏报告/产物，不把全部运行历史注入主 Agent。

1. 工具缺失：只查看 Codex 配置中的 oea 条目和对应启动错误，不读取其他服务的凭据或整份配置输出。
2. GATEWAY_UNAVAILABLE：检查已记录的 loopback URL、当前宿主进程和限定日志片段。客户端文件保存的是定位与认证信息，不把 client-token 展示给模型或复制进脚本正文。
3. 参数错误：查询当前 area/action 的 guide；不靠重复提交尝试未知字段。
4. 进程 Agent 失败：读取该 task 的错误与受管日志，核对解释器、依赖、JSONL、descriptor 和退出边界。独立测试使用另一个仓库外数据目录。
5. 超时/断连：先查任务或 MCP 调用记录再决定后续。不能换幂等键重放具有未知结果的外部动作。

只有任务确实需要且已有授权时才停止宿主；先确认活动任务与 UNCERTAIN，优先正常停止。不按模糊进程名杀死所有 Python，不自动重启用户服务来刷新代码。

## 备份与升级

平台已有 CLI `python -m oea backup --data-dir DATA --output BACKUP` 和嵌入式 Runtime.backup；管理 MCP 当前不直接暴露恢复、迁移或宿主终止。

备份使用指定的仓库外目录。CLI 会独占工作区；不能在宿主运行时强行启动第二个 Runtime。维护窗口先处理活动、排队和等待任务，确认离线后再执行备份，避免启动离线 Runtime 时意外恢复未决任务。备份包含私有业务数据，不能随源码提交或擅自上传。

升级保留现有配置、状态库和受管备份；只运行任务需要的契约检查。恢复备份、清理状态或降级必须有具体目标与影响范围，不能通过直接修改 SQLite 或删 host.lock 绕过互斥和迁移校验。

如果用户明确要求修复 MCP 接入但当前工具不可用，可以用已安装 SDK / HTTP 接口诊断管理链路，说明正在使用回退方式；这不授权绕过外部服务的访问限制。
