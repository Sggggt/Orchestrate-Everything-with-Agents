# 应用接入

外部应用管理自身代码、进程、界面和业务编排；OAP 只提供获准 Agent 的调用服务。
应用接入复用既有 Host、LangGraph、回执、预算和原生沙箱，不创建另一套执行循环。

1. 确认目标应用、来源项目、已保存 Agent 和所需能力。管理端用 `host.status` 核对支持 OAP 的宿主。
2. 通过 `applications.create` 登记应用，或读取既有登记。凭据只在创建和轮换时返回；写入获准秘密配置，不在聊天或公开文件中展示。
3. 查询 `applications.bind` 的单个操作 Schema，保存明确的项目、Agent 与 ApplicationGrant。工具、Skills、资料、环境、网络和预算只授予任务所需范围；可信扩展单独授权。
4. 应用后端使用 `ApplicationClient` 和应用凭据，读取 `capabilities` 与获准绑定，按稳定幂等键创建会话、提交工作。应用不能透传任意平台管理操作。
5. 同一会话沿用专用实例与目录。读取原状态、事件和结果；等待时恢复原 Run，断线重连保留事件游标，用 `response` 补读原响应。取消请求与真实停止分别核验，未知结果先用 `actions`／`action` 读取原回执，核实外部结果后用 `confirm_action` 确认原动作，再恢复原 Run。
6. 附件先提交大小与哈希，再流式上传；读取原上传状态后核对提交。发布文件从所属应用接口下载并校验哈希。应用记录不从普通工作台、控制 MCP 或管理 SDK 的业务列表读取。

应用调用不具备平台群聊、成员目录、inbox、manager 或委派能力。应用自行安排多个独立 Agent 调用。
绑定调整与当前撤权仍约束后续工具调用；应用关闭或删除不等于其外部业务副作用已回滚。

安装代码中的 `oea.contracts.applications` 提供类型，在线 `/api/oap/v1/schema/{operation}` 提供当前请求 Schema。
只读取本次动作需要的定义，不把完整协议或全部配置加载到上下文中。
