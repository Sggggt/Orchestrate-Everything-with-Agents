# Agent 执行架构

本流程设计单个 Agent 的模型、工具、状态、分支和交付。组织多个独立 Agent 的业务步骤使用[业务编排](orchestration.md)。仅加载当前动作协议，不读取完整节点目录和所有历史。

1. 确认目标、现有 Agent 权限和可验证结果。用 `architectures.status` 读取当前默认版本与修订。已有授权内继续工作；架构配置不扩大工具、模型、Skill 或工作区授权。
2. 从 `architectures.templates` 选择 `react`、`plan_execute` 或 `reflexion`；确定性处理使用状态、条件和纯函数。只对需要的节点调用 `architectures.node_types`。任意原生 LangGraph 使用本地源码和 SDK 显式注册工厂，控制 MCP 不执行 Python 字符串。
3. 用 `architectures.create` 创建带 `owner_agent_id` 的项目草稿，或 `architectures.get` 读取所选草稿后按修订 `save`。需要完整高级结构时用 `ArchitectureBuilder`／`ArchitectureGraph` 编辑；`adjust` 仅用于明确暴露的选项。`export` 返回源码，写文件与注册、发布、生效分别核验。
4. 用 `validate` 定点修复节点与字段错误。静态校验不调用模型，不证明循环收敛。状态只保存小型数据和引用；并行分支保持纯计算，Context 和能力动作在汇合后提交；复杂能力并行用独立实例或明确的代码图。
5. `publish` 生成不可变候选。用 `architectures.run` 在明确实例中试运行，保留原 `RunSpec` 幂等键、项目和根预算；独立上下文选择独立实例。试运行不改变 Agent 绑定，但其中的模型、工具和副作用均为真实执行。
6. 用 `inspect` 读取所选 Run 的一页实际节点，再用 `node_result` 或原 action／context 引用核对证据。分别判断执行完成、工具效果和内容质量。P&E 检查计划与步骤结果；Reflexion 检查下一次尝试是否读到了原反馈和经验。
7. 在目标和现有授权允许生效时，使用 `compare` 核对变更，再按 Agent 当前修订 `bind`。默认绑定允许切换，历史运行、等待或未结清用量不阻塞；仅之后新接受的 Run 使用新版本，已接受及恢复的工作保留原图。共享架构发布不自动改变任何 Agent 的版本；回退也通过明确绑定旧版本。
8. 故障沿原 Run、图位置和回执恢复。成功回执后的重入不重发；超时或未知副作用先核对原动作。不要换新键、用反思重试或改架构绕开待核对结果。旧检查点未经验证不套用新节点名，按离线迁移流程保留。

交付说明当前绑定、候选版本、试运行证据、实际质量和未验证范围。浏览器设置页提供可点击画布预览、Agent 专属草稿和确认切换；全屏画布支持声明式节点、状态、映射、子图及独立试运行。保存不生效；删除草稿保留不可变版本和运行证据。任意 Python 代码图仍通过 SDK 注册，画布只读展示。大结果通过原 `result_ref` 和项目读取所需范围，不重放写操作补输出。
